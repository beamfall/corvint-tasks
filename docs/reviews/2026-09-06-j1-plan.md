### 1. Closed receipt paths and post semantics

Receipt paths use archive namespace: intent/queue.json, intent/policy.json, intent/import-map.json, intent/tickets/<local>.json for projections; and VERSION, barrier.json, reservations.json, requests/<xx>/<digest>.json, attempts/<attemptId>.json, effects/<key>.json, pinned/<digest>.json, evidence/<digest> for private state. Paths are clean relative slash-only strings within Identifier128 bound, with exact key/name grammars and no arbitrary traversal. head.json, receipts/, worktrees/, effect .boot/.ack, temp paths, and symlinks are forbidden receipt post destinations. Head is derived control state; bootstrap is separately governed. Content-addressed bytes must match their path identities.

Pre and post path sets are duplicate-free and exactly paired for this increment. Their ordering is canonical byte order. Updates require the pre digest or absence; afterimages are canonical complete bytes: inline JSON object up to64KiB (at most8) or content-addressed blob (used for raw VERSION and larger/remaining records), exact post sha256. Check digest when reading the bytes; do not use a manifest-provided digest as proof of a filename identity. Receipt maximum1MiB, global JSON caps remain unchanged. Kind, outcome and code enums are closed; seq≥1, prev null iff seq1, headGeneration nondecreasing; scope IDs must belong to the selected queue.

One explicit all-null post means deletion: sha256:null, record:null, blobSha256:null. It is legal ONLY for kind UNPAUSE and path barrier.json, with a paired non-null pre digest. No other deletion is accepted. A pure redo classifier defines absent=already applied, exact pre=delete eligible, third digest=JOURNAL_FORKED. It does no unlink. PRUNE and deletion of receipts/evidence stay unsupported; retained history must remain a contiguous 1..lastSeq chain and every referenced byte remain available.

### 2. Genesis without circular hashes

Define head.initSha256 = SHA256(complete canonical receipt1 bytes). Receipt1 must be INIT, prev:null, headGeneration:0; no later INIT is valid. Freeze one small closed descriptor profile taskman-init/0 with fields profile, queueId, primaryWorktree:PathText, versionSha256:Digest. Its content-addressed pinned/<digest>.json afterimage occurs exactly once in receipt1 and nowhere else as a newly posted INIT descriptor. Receipt1 MUST also post VERSION with pre.sha256:null and a verified blob containing exactly taskman-state/0\n; a descriptor digest alone is insufficient. Receipt1 MUST post initial intent/queue.json, intent/policy.json and empty reservations.json afterimages, all with null preconditions, alongside its unique INIT descriptor (also pre:null). Decode these required genesis records, require the same queue identity and no reservations/live attempt/effect posts; no arbitrary pre-existing post target is accepted by genesis. VERSION bytes and digest must agree with descriptor and head. Head.primaryWorktree and queueId agree with descriptor; head.versionSha256 agrees with VERSION. The INIT receipt never posts head.json. Each later receipt derives lastSeq/hash/generation without changing genesis identity; relocation is outside J1 and must not silently pass this rule.

A read with no head and no receipt1 is UNINITIALIZED; no read creates or cleans anything. A no-head store with a valid linked receipt1 (and complete required genesis blob evidence) is REDO_PENDING, never an empty new store. A malformed/conflicting linked genesis is JOURNAL_FORKED (or the existing strict malformed/unsupported code for its precise cause), no repair. Precommit directory/blob/temp remnants without receipt1 remain UNINITIALIZED with staging presence reported; no validity or cleanup claim. J3 must later freeze stable request-bound INIT retry and staged-artifact accounting before its writer is built. J1 does not pretend to solve safe mutation of those remnants.

### 3. Request replay proof using the existing receipt post

Every receipt with non-null requestId must contain exactly one request-index afterimage at requests/<first2>/<SHA256(exact UTF-8 requestId bytes)>.json. Entry is the closed object {requestId, seq:Size, mutationSha256:Digest, outcome:<complete taskman-outcome/0>}; requestId max64; outcome requestId and receiptSeq equal entry/receipt, outcome outcome/codes equal receipt outcome/codes, other receipt outcome fields agree wherever explicitly present. No receipt hash in the entry (no circular digest). This uses existing post digest binding, no new mutationSha256 receipt field. Null requestId prohibits posting a request entry. A requestId occurs once in history; later identical invocation compares its recomputed canonical mutation digest with this receipt-bound digest and returns the original outcome. Input bytes cannot be reconstructed from the digest and audit does not claim to do so.

For indexed lookup, change the internal mutation.RequestIndex contract to Lookup(requestId) (IndexEntry, bool, error). This is an unpublished internal API, and the explicit error return is smaller and safer than a prepared-adapter capability protocol. Update MemoryIndex and its call sites/tests; Apply/Adopt must refuse on lookup error, never map it to false or emit a fresh plan. A fully retained audited adapter may answer immutably; a streamed adapter completes a bounded snapshot audit and projection check on every lookup and propagates any read/movement/corruption error. Only verified absence returns false,nil. Request projection must agree with the receipt-bound afterimage; missing/corrupt projection fails. Add injected read failure after initial successful construction/audit, exact replay and corruption witnesses. State snapshot identity must remain available to the caller; no cross-snapshot atomic transaction claim from this pure library. No trusted caller binding is minted.

Then stream the expected chain, never retain all receipt bytes. An optional single next receipt is classified REDO_PENDING only if seq/prev continue the head and every required bound/byte check passes; another or a gap is JOURNAL_FORKED. Archive audit never permits pending receipts. Validate head last digest/generation and genesis identity, post/blob identities and request bindings. Retain only requested latest records plus bounded digest/index metadata; support selected lookup/audit without materializing all projected bytes. A full index adapter may be explicitly bounded by aggregate live state limits and must fail LIMIT_EXCEEDED before allocation rather than pretend completeness. Do not add an arbitrary small request limit below the supported store; provide streamed lookup when complete materialization would exceed the profile budget.

Capture and recheck the stable head/receipt inventory and intent tuple around audit per existing snapshot protocol; on movement retry boundedly or return SNAPSHOT_MOVED. Reads never lock/write/redo.
