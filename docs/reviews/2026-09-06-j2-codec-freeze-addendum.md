Status: concrete experimental mechanics proposed for independent Gate A; no writer, CLI, runtime, migration or upstream acceptance. Sources are `tcp02-j2-capacity-plan-r2.md`, `tcp02-journal-plan-r3.md`, `j2-unpause-codec-parity.json`, and read-only `tcp02-j1-review-snapshot`, especially `docs/SPEC.md` §§3.1/3.3/3.4, TM-V0-005..008, `internal/snapshot/{head,receipt}.go`, `internal/mutation/{adopt,outcome}.go`, and `internal/journal/audit_test.go`'s physical-pre witness. ## Release split and authority

**J2a is independently PASS and already building:** pure supplied-manifest entry count, payload sum, canonical-manifest size and exact-tar size with checked arithmetic. Inventory/delta and transition-prefix accounting remain J2b work. It needs no administrative command, new staging layout or new accepted behavioral contract. Its result is a cost, never authority, writer admission or durability evidence.

**J2b is the next bounded pure model:** the five command templates and one staged-transaction representation below; exact prefix/abort/UNPAUSE costing; no filesystem effects. These clarify unpublished local mechanics under the existing build instruction. Root selected the conservative existing-hard-caps alternative: **1,000,000 receipts and 4 GiB remain hard ceilings.** The model reserves one successful UNPAUSE inside them whenever a barrier exists or is being installed. Ordinary work may therefore refuse before those ceilings. This supersedes the operative extension in r2; there is no 1,000,001-receipt or 4GiB+1683 writer allowance.

No new owner acceptance is inferred. The supplied accepted ATCP-V0-015/018 require bounded pinned-policy accounting, saturation without discarded records, and declared persistence limits; the literal 1m/4GiB pair was found in the generated local mutation freeze, not in the searched ATCP/ATM bodies. In any event this selection preserves the stricter current cap and does not exceed a pinned or owner limit. Increasing a genuinely accepted/pinned cap, weakening barriers/authorization, deleting replay history, or enabling real queues/runtime remains outside this packet and would require the applicable acceptance record. Administrative actor authentication remains NOT_OBSERVED in a pure model; a supplied actor value is not a grant.

J2b accepts fixture queues only, with no attempts, pending effects, bootstrap artifacts or worktrees. It may model any structurally valid barrier for UNPAUSE/reconciliation; PAUSE never replaces a different barrier. Live/terminal runtime escrow, restore and prune remain held. J3 additionally requires trusted authorization binding, filesystem qualification, ownership, durability and crash/cleanup proof.

## 1. Closed administrative digest preimages

For every row, digest = SHA256 of `wire.EncodeFile` of exactly the listed closed object; LF included. `actor={id:label,role}` comes from the separately trusted binding, never a projection or envelope claim. requestId is 1..64 bytes; queue/target IDs use their existing grammar and scope. All `*Sha256` fields are existing Digest values checked against the specified captured bytes. These are preimage objects, not new persisted authority profiles.

| Operation | Complete closed preimage |
|---|---|
| INIT | `{actor,operation:"INIT",policySha256,primaryWorktree,queueId,queueSha256,requestId,versionSha256}` |
| PAUSE | `{actor,operation:"PAUSE",queueId,reason:"OPERATOR",requestId,scope:"ADMISSION"}` |
| UNPAUSE | `{actor,operation:"UNPAUSE",queueId,requestId}` |
| KEEP_JOURNAL | `{actor,canonicalSha256,fileSha256,operation:"KEEP_JOURNAL",queueId,requestId,targetId}` |
| ADOPT_FILE | `{actor,fileSha256,operation:"ADOPT_FILE",queueId,requestId,targetId}` — exactly the existing `mutation.AdoptDigest` |

INIT's queue/policy inputs are complete validated canonical desired afterimage bytes, already frozen before digesting; the queue is fixture:true. VERSION is exactly `taskman-state/0\n` (16 bytes); reservations and the INIT descriptor derive deterministically from the queue/primary identity. Do not regenerate a different initial queue/policy timestamp on retry. Current head/sequence/generation, output receipt timestamps and outcome fields never enter these preimages. PAUSE's restricted reason/scope is this subset, not a change to cutover/drain behavior.

For KEEP_JOURNAL, canonicalSha256 is an explicit original-request precondition on the chosen canonical record; fileSha256 is the explicit digest of the projection bytes whose discard was chosen. Preserve both on retries; do not silently rebuild the original request from a later head/projection. This binds which canonical content the operator selected as well as which bytes may be discarded. ADOPT_FILE retains its existing digest unchanged; adding a current revision/hash there would break its frozen replay identity.

After validating actor binding/role, request shape and queue/target identity, consult the verified request index before new-transition preconditions. Same requestId + same digest returns the original full outcome with replayed:true, no writes/posts/staging. Different digest is REQUEST_ID_CONFLICT, no writes. Index corruption/I/O never means absence. A retry must supply the same immutable request inputs, including the original offered/discarded bytes or their explicitly bound original digest as appropriate; re-reading a changed projection does not reconstruct that request.

## 2. Exact successful/no-change/refused decision shapes

The pure model returns `Transaction`, `Replay`, `NoChange` or `Refused` as an internal discriminator; this is not a new external wire profile. Successful fresh transactions use the existing receipt/index/outcome codecs. Every fresh successful receipt has non-null requestId, exactly one request-index post, outcome COMPLETED, codes=[], recordedAt equal to the frozen model timestamp, and expectedSeq=base.lastSeq+1. Head generation is preserved (INIT establishes zero). attemptId/generation are null throughout this subset.

For INIT/PAUSE/UNPAUSE, receipt.ticketId and expectedRevision are null; outcome resultingRevision/resultingAcceptanceRevision are null. For either reconciliation, receipt.ticketId is the selected ticket, expectedRevision is C.revision, and the outcome's two revisions equal its posted ticket. The original outcome has replayed:false and receiptSeq equal to the receipt/index seq. No caller-supplied successful outcome is accepted. Null-versus-empty, path ordering, inline/blob and profile checks remain J1's strict checks.

`NoChange` carries no receipt, index entry, post or staging plan. If represented as taskman-outcome/0, it is COMPLETED, replayed:false, receiptSeq:null, both resulting revisions:null, codes=[]. It does not claim a durable successful transaction or reserve the requestId. Likewise refused requests have no recorded index/receipt; reusing an unrecorded ID is not an identical committed retry. This explicitly avoids infinite denial/no-op history growth.

| Command | Fresh successful transaction | NoChange | Refusal/scope boundary |
|---|---|---|---|
| INIT | Empty genesis targets; exactly J1's six indexed INIT posts; all pre null | None | Existing initialized store with a new request is BLOCKED, codes=[]; recorded identical INIT replays first. Relocation/existing-queue adoption/extra genesis posts are unsupported. |
| PAUSE | No existing barrier; create ADMISSION/OPERATOR barrier with actor id, sinceSeq=new seq and since=recordedAt; reserve UNPAUSE first | Already ADMISSION/OPERATOR after permission checks; preserve its actor/time/seq exactly | Another barrier is BLOCKED/PAUSED; never overwrite it. ALL's prohibition on PAUSE remains in force. Other requested reason/scope is unsupported in this subset. |
| UNPAUSE | Delete one existing, validated barrier with paired non-null physical pre; fresh request index only other post | Barrier absent | Actor/policy refusal writes nothing. A valid ALL or other-reason barrier is not weakened until this separately authorized UNPAUSE; the zero-attempt/effect scope still applies. |
| KEEP_JOURNAL | A present regular projection D differs bytewise from canonical C; retain D as raw evidence and restore exact C | D and C bytes identical, after replay/precondition checks | Missing/nonregular/unbounded projection, wrong chosen canonical digest, wrong file digest, branch mismatch or authorization refusal produces no fresh plan. |
| ADOPT_FILE | Exactly existing mutation.Adopt validation/composition/finalization, including revision +1 and derived acceptanceRevision | None added here | Preserve existing role/tombstone/protected-field/liveness/limit refusals. An accepted empty composition still creates one revision; do not turn it into a new no-op. |

The modeled principal subset is OWNER/OPERATOR, with policy allowed only to remove permission, never add it. This follows the existing reconciliation roles and operator administrative path as a restrictive implementation selection; it does not authenticate a caller or establish an upstream role grant. The future writer must obtain the applicable trusted binding/authorization before using a modeled transaction. No model-only permission flag grants execution.

Preserve existing refusal outcome/code mappings for malformed/version/limit, request conflict, storage, branch and permission checks. The few subset refusals above use existing BLOCKED/PAUSED or UNSUPPORTED, rather than inventing ALREADY_* wire codes. Structural invalidity is not NoChange. Transient staging preparation is an internal `PreparationPending` observation; it is not renamed REDO_PENDING before a receipt is linked and gets no new public code from J2b.

## 3. Physical precondition versus canonical predecessor

For reconciliation, capture C from the selected journal snapshot and D from the operator-selected physical projection. Check the request's original digests against these inputs before a fresh plan. `receipt.pre[ticketPath]=SHA256(D)` is the physical redo guard, even when it differs from the preceding canonical post digest. The command's explicit choice permits only that observed D to be replaced; a later third value must refuse/hold, not be overwritten.

KEEP_JOURNAL posts C byte-identically: revision, acceptanceRevision, previousRecordSha256 and metadata do not change. It additionally posts `evidence/<SHA256(D)>` with post sha256=blobSha256=SHA256(D), record:null; its paired pre is null if genuinely absent, otherwise the digest of the verified already-existing same bytes. This uses J1's existing content-addressed post form, not a new receipt field. The same raw evidence slot can serve that post; count the path once. Empty D is permitted as raw evidence after the pending J1 repair; D is bounded by the existing 128 KiB ticket file limit and need not parse as a ticket. Absent files are outside this narrow variant, not silently represented as empty bytes.

ADOPT_FILE posts C' from the existing reducer: C'.previousRecordSha256=SHA256(C), not SHA256(D), revision increments once, and acceptanceRevision follows the existing criteria. No new discarded-evidence obligation is imposed on ADOPT_FILE by this packet. C/D remain distinct in the pure input/plan even though only the existing receipt fields are serialized. J1 continues to report historical reconciliation authorization/evidence completeness NOT_OBSERVED; valid checksums alone do not prove this writer-side choice.

## 4. Closed staging descriptor and artifact assignment

The proposed descriptor has exactly eight fields:

`{profile:"taskman-stage/0",queueId,operation,requestId,requestSha256,recordedAt,base,artifacts}`.

operation is exactly INIT/PAUSE/UNPAUSE/KEEP_JOURNAL/ADOPT_FILE. base is null only for INIT; otherwise exactly `{lastSeq:Size,lastReceiptSha256:Digest}` from the stable ordinary base. No extra actor/authority field is needed: the immutable request digest binds actor and the receipt artifact contains that binding. recordedAt is the frozen timestamp needed to reproduce output even if a crash precedes receipt staging; it never supplies liveness/authority.

Each artifact is exactly `{slot,role,target,sha256,bytes:Size}`. role is RECEIPT/HEAD/POST/EVIDENCE. Build the set below, sort by (role,target) in byte order and assign consecutive slots a00..a10. `artifacts` is explicitly a semantic array in slot order; slot, (role,target), and actual target file are unique. The only cross-role deduplication is an evidence path already represented by a POST: it has one POST artifact, published in the precommit evidence phase. Other equal bytes at different paths remain separate artifacts/costs. No arbitrary destinations or caller-selected file bound.

- RECEIPT: exactly `receipts/<nextSeq padded to12>.json`, one, bound 1 MiB; INIT nextSeq=1, others 2..1,000,000. Minimal UNPAUSE additionally has its proved 1,683-byte bound.
- HEAD: exactly `head.json`, one, bound 4 KiB; bytes must equal the derived head, including genesis receipt hash. It is never a receipt post.
- POST: exactly the non-deletion posts of the modeled receipt, with existing PostBound and content/path identity checks. INIT has VERSION, intent/queue.json, intent/policy.json, reservations.json, the unique pinned INIT descriptor and the request path; PAUSE has barrier/request; UNPAUSE request only; KEEP has ticket/request/discarded evidence; ADOPT ticket/request.
- EVIDENCE: exactly the distinct required blob paths absent from the starting inventory and not already represented by an evidence POST. Each derives from verified promised bytes, never a digest-only claim. INIT can need VERSION, queue and policy blobs (three); KEEP at most its canonical-ticket blob after the discarded-evidence POST; ADOPT at most one ticket blob; PAUSE/UNPAUSE none under the fixed success shapes.

For a full frozen plan, declared sizes/digests must equal the actual encoded bytes, the receipt posts/request preimage and the derived head. For interrupted preparation, missing/partial artifact bytes cannot pass that full-plan check; classify explicitly as preparation while checking their assigned name/type and observed length<=declared bound. Do not claim complete transaction validity from the descriptor alone. A complete wrong digest is corruption. Before any use, reject unknown/missing/duplicate keys, noncanonical encoding, invalid queue/request/timestamp/digest, wrong role/path/count/slot, overflow, incorrect base/seq or byte cap, symlink/directory artifacts and unexpected names.

### Computed descriptor cap

**MaxStageDescriptorBytes=2,422 including LF.** This is the maximum encoded length under the structural descriptor field/path/role bounds below; complete codec/transaction coherence may reduce it. It is deliberately not a claim that all maximum payload sizes coexist in a reachable transaction. No broad JSON parser widening is required. `active.json` and `active.json.tmp` both have this cap before parsing/reading.

| Operation | Maximum slots | Safe descriptor bytes under structural bounds |
|---|---:|---:|
| INIT | 11 | 2,422 |
| PAUSE | 4 | 1,243 |
| UNPAUSE | 3 | 1,098 |
| KEEP_JOURNAL | 6 | 1,676 |
| ADOPT_FILE | 5 | 1,467 |

Length derivation uses actual admissible targets, not generic 128-byte escaped paths: receipt26, head9, VERSION7, queue17, policy18, reservations17, pinned76, request81, evidence73, ticket20+localBytes. Queue IDs are ASCII and at most128 bytes; a scoped ticket imposes queueIdBytes+localBytes<=126, so use queue62/local64 (or another maximizing split), not impossible queue128/local64. RequestId contributes at most128 encoded bytes, digest64, timestamp20, slots3. INIT base=null; an eligible non-INIT base has lastSeq<=999999 (six digits) because a new receipt must fit the unchanged 1m hard cap. The non-INIT base contributes its two closed members and fixed digest. Each artifact contributes the five keys/punctuation, role width, exact target width, digest64, slot3 and decimal byte-count width.

INIT's maximal slot set uses declared receipt cap1048576/head4096; POST byte bounds VERSION16, queue1048576, policy262144, empty reservations194, INIT descriptor8465, indexed INIT551; and EVIDENCE lengths16/1048576/262144. Empty reservations194 and INIT descriptor8465 derive from their actual closed encoders with queue128 and maximum encoded PathText. The latter is a conservative independent field bound: a simultaneously valid 4KiB head may restrict primaryWorktree further, but does not increase its four decimal digits. Other rows use existing destination caps; fixed successful request entries are at most563 bytes for administrative commands and579 for reconciliation (two maximum Count revisions replace null). KEEP/ADOPT use ticket/evidence<=131072. These inputs reproduce the table by canonical ASCII JSON length arithmetic. A future Go descriptor encoder must supply parity/maximizing-shape witnesses before this number governs artifacts.

Use `staging/{active.json,active.json.tmp,a00..a10}` only, flat/no symlinks/no extra names. Eleven artifacts plus two descriptor names plus the directory yield at most fourteen scanned entries. Export excludes only these declared transient files from F/M/T/Jn/Jb/Eb, while charging every entry to D and its logical bytes to Pb; linked orphan evidence remains included in archive and evidence budgets. New read/export treatment remains a proposed local layout amendment, not behavior delivered by J2b. Non-staging legacy temp cleanup stays unsupported by this writer subset without a separate proof.

## 5. Reserve and interrupted-abort closure, with unchanged hard caps

Umax=1683, index max563 and outcome max308 are supported by `j2-unpause-codec-parity.json` for the maximal minimal-UNPAUSE template. The probe's seq1000001 and a maximum-generation value are codec-domain upper witnesses, not permission to exceed the selected count cap; seq1000000 has the same seven-digit width. Relevant codec changes invalidate this evidence. Actual head bytes are rederived and must fit the existing head cap; reserve must consider a decimal sequence-width increase before installing a barrier.

Before any fresh modeled transaction, prove its complete branch and every publication-prefix -> permitted abort-prefix -> fresh successful UNPAUSE branch within all existing hard caps and individual file/intent bounds. If the resulting state retains/creates a barrier, it must leave capacity for one Umax receipt: `Jn(proposed)+1<=1,000,000` and `Jb(proposed)+1683<=4 GiB`, plus exact archive/manifest/evidence/scan/staging costs. An eligible successful UNPAUSE may consume that reserve, never exceed a hard cap. An unbarriered store may use the last ordinary slot; a fresh PAUSE there refuses before staging. No promise of simultaneous ordinary maxima beneath a barrier is made.

UNPAUSE's peak retains the old barrier while adding its receipt and index; deletion cannot fund those earlier additions. Reserve a missing request shard and all staging entries. Its three artifact byte caps sum1683+563+4096=6342; two simultaneously charged UNPAUSE descriptors add2*1098, so conservative modeled logical temporary peak is **8,538 bytes**, and staging scan peak is five files plus staging/ (six entries). Actual encoded head/per-file feasibility must still pass; neither this number nor Pb is disk preallocation or ENOSPC immunity.

Retain r2's reachable abort: under J3's future sole-writer/identity proof, unchanged ordinary base + complete receipt inventory with no linked next/extra receipt + zero effects + descriptor-owned staging permits authorized abandonment before receipt link-in, without original request bytes. Only evidence may have been published; retain every linked orphan and all history. Partial descriptor-listed slots are recognized by type/name/observed length<=promise, not a nonexistent full digest. Delete artifact slots and descriptor temp, fsync staging, then delete active.json and fsync staging again; only then discharge abandoned afterimage obligations/start fresh UNPAUSE. Completed mismatching artifacts are corruption/hold. No age-based cleanup, new abort receipt or extra artifact. Keep all abort-prefix costs and old projection sizes; never credit an abandoned intended shrink. J2b models these states but cannot prove their filesystem ownership/durability.

An already saturated store with a live barrier and no closure reserve is not retroactively writer-eligible. Preserve its bytes/read/export and report the invariant failure; no truncation, invented reserve or hard extension repairs it. A valid committed pending UNPAUSE redoes its existing receipt without consuming another slot; a fresh request cannot spend its reserve twice.

## Selected Gate A repair: descriptor-less preparation

A crash before active.json publication may leave only the fixed active.json.tmp. Classify this as `TempPreparationAbortable` only with a stable unchanged base, complete receipt inventory with no linked next or extra receipt, zero attempts/effects, no active.json, no artifact slots, and no unknown entry. The only file may be the regular fixed temp with length no greater than MaxStageDescriptorBytes=2422. Its bytes need not parse, even if full-length or malformed: without active.json it never authorized payload production. Malformed active.json or any descriptor-less payload remains a hold. The pure cleanup sequence unlinks only that temp, then fsyncs staging before a new descriptor may begin. Charge its bytes/name through the durable cleanup step; no new artifacts or history deletion. J3 must prove fixed-name ownership/type/identity. Witness every truncation length, malformed bounded temp, cap+1/nonregular/unknown/stray-artifact refusal and cleanup interruption. ## Selected Gate A clarification: pure administrative authorization boundary

The existing policy Operations/DefaultRoleMatrix describes ticket operations only. J2b must not invent administrative policy rows, pass PAUSE into that ticket matrix, introduce a default-allow permission flag, or infer authentication from a supplied role. Administrative templates accept a well-formed hypothetical OWNER/OPERATOR binding and report ActorAuthentication and AdministrativeAuthorization NOT_OBSERVED; their output grants no write permission. Existing ticket-policy restrictions remain enforced by mutation.Adopt composition. J3 must separately obtain and validate applicable administrative authorization and pinned/upstream restrictions before consuming any modeled transaction; the pure model alone is insufficient. Independent Gate A confirmed this clarification, with no remaining HIGH/MED.
