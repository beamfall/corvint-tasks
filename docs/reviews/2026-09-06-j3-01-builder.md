## Mechanism decisions

Session mutex precedes `Lock.mu` for an entire operation, including checks, native calls,
sync, cleanup and handle closes. Session close waits on that mutex, joins handle/release
errors and retains its first result on repeated close. Constructor failure closes new handles
without releasing the caller's lock. Successful construction adopts explicit lock release.
If an external `Lock.Close` wins, that caller receives its first-call release error under the
existing public lifecycle contract; session close does not replace that contract. No lock.go
edit was needed, and every concurrent close result is observed in the tests.

Parents are retained through safeopen; native cross-parent calls pin both parents plus source
and, for rename, the opened expected destination under Control. Checks compare actual
lock/common/state/parent/name identity and relevant file bytes/mode/mtime/size. Source tokens
are session-owned and only issued after complete preparation, strict file sync, directory
sync and close. Partial cleanup compares the actually written prefix and inode, preserving
unknown/foreign bytes. Full successful preparation is independently re-read and hashed.

Closed names and bounds are specified in SPEC §5.1.1: descriptor temp/active and eleven payload
slots; immutable exclusive destinations; private mutable head/barrier/reservations; barrier
and owned-stage removal; absent-only intent publication. Request files keep J1's 64 KiB cap.
Evidence and pin names bind staged byte digests. Empty raw evidence is distinct from absence.
Link keeps its source; rename syncs both source and destination parents; mkdir syncs child
and parent; no history or existing intent may replace/remove, and no recursive cleanup exists.

Darwin native constants/signatures were checked against the installed Go 1.27.0
`cmd/vendor/golang.org/x/sys/unix/zsysnum_darwin_{arm64,amd64}.go` and generated syscall
wrappers: renameat 465, linkat 471, unlinkat 472, mkdirat 475. No third-party package is imported.
Linux uses stdlib syscall constants and Renameat (including Go's architecture-specific
renameat2 fallback). Darwin device/fsid/type and mounted-on/from identity, or Linux device/
filesystem and descriptor-bound fdinfo mnt_id, must be unambiguous and match the retained
observation. Unknown/unsupported observations explicitly refuse; st_dev equality is not enough.
EXDEV does not copy or remove anything. Strict Darwin full sync remains the accepted explicit
F_FULLFSYNC implementation, with directory fsync separate.

After-effect errors preserve that create/link/rename/unlink/mkdir happened, even if later sync,
cleanup or close failed. Errors join rather than discard simultaneous failures. Equal-post
private state and already-absent barrier still require durability checks. This is not atomic
content-CAS against arbitrary editors, and these errors are not transaction-commit evidence.
