## Delivered mechanics

`MeasureManifestEncoding` returns exact `Files`, `PayloadBytes`, `ManifestBytes` and `TarBytes`
for a hypothetical typed `Manifest`. Metadata is validated through the existing closed decoder
on the bounded empty-files production encoding after scalar validation. Members are independently
validated for Identifier128, clean Path, digest, canonical Size, int64 representability,
per-path bound, the reserved manifest name and duplicate paths. Count is rejected before metadata
encoding or uniqueness allocation.

Manifest size is the empty-files production encoding plus each production `entryValue` length
and comma. Tar size uses a fresh standard-library tar writer per shared production header to
count PAX bytes, then checked round-to-512 body arithmetic and one 1,024-byte trailer. No complete
manifest or member body is allocated. File-count, manifest and exact-tar caps and arithmetic
overflow fail closed.
