## 1. MED — active-plus-temp must use the frozen descriptor’s exact length

**Plan evidence:** lines 21 and 35 describe globally bounded descriptor/temp reads and allow a bounded temp beside active without the final J2b equality constraint.

**Original code:** `tcp02-j2b/internal/transaction/stage.go:137–143` requires `len(temp) <= len(active.Data)` and, at equal length, byte equality with active. The global 2,422-byte arbitrary-temp exception is only the no-active case at lines 102–115.

**Counterexample:** a valid 900-byte active descriptor plus a 901-byte temp is below 2,422 and would pass the current prose, but J2b refuses it. A different 900-byte temp is equally invalid even if it parses as another valid descriptor. Treating these as ordinary ignored staging would produce incompatible native read and pure-model classifications.

**Selected smallest amendment:** read/validate active first when present; bound its temp by the actual active byte length, refuse excess with LIMIT_EXCEEDED, and require exact bytes when lengths are equal, otherwise JOURNAL_FORKED. Shorter temp data remains interrupted preparation. Only without active may the single bounded temp contain arbitrary zero-length/partial/malformed bytes up to 2,422. Read-only observations must not borrow abort authority from that exception.

**Witnesses:** active length N with temp N−1, identical N, different N, N+1 below 2,422, and no-active arbitrary bounded temp. Assert both shared/native observer results match the final J2b rule and create no source effects.

## 2. MED — the existing Source API cannot supply the promised root tuple/lifetime

**Plan evidence:** line 11 excludes `journal/source.go` from changes; lines 21 and 50 promise retained native parents and actual state-root/visited-parent identities, including empty roots.

**Original code:** `tcp02-j2b/internal/journal/source.go:21–29` returns only child entries from List. `Native.List` at lines 59–89 opens then closes its directory without returning that directory’s own identity. `Native.Read` at lines 51–57 independently reopens an absolute path. The current journal observation map contains directory children but never the state root itself. Existing archive listing similarly closes its directory before later body reads (`internal/archive/layout.go:50–74,185–212`).

**Counterexample:** replace the state root with a different directory and move all existing children into it, preserving child identities/bytes/metadata. Existing Source results can be identical while the root identity changed. Empty-directory observations are weaker still. Separately, listing under one opened parent and then reopening a replaced absolute path for body bytes cannot substantiate the claimed retained-parent read lifetime.

**Selected smallest amendment and ownership:** include `internal/journal/source.go` and its focused tests in the claim. Change the existing bounded directory-list result to carry **the listed directory’s own `os.FileInfo` alongside its child entries**, obtained from the same retained handle that performed the listing. A small concrete result such as `{DirectoryInfo, Entries}` is sufficient; it is read metadata, not a capability framework or authority token. Update the internal Source interface and fixture/decorator implementations explicitly so missing directory observations cannot silently become “verified.” Preserve the scan bound: the directory identity is not an extra enumerated child or an extra D charge.

For the native implementation, introduce only an internal per-attempt native read lifetime: pin the state and intent roots, retain/reuse the listed no-follow parent handles through that attempt’s capture/body/recheck, and close them on every exit before another attempt. Native file opens use those parents; root/path binding is re-observed against the retained identities so a detached root is not silently treated as the currently named store. Archive uses its analogous archive-local lifetime. This requires no change to `snapshot.Reader`, no new public Reader option, no general session/capability architecture and no second retry owner. Non-native fixture Sources supply explicit directory observations under their existing synthetic byte-source contract; they do not thereby claim host filesystem observation.

The API form may retain the old Source interface through a tiny optional directory-observation extension **only if every caller requiring this tuple explicitly refuses unavailable observations**. An optional method with a zero-value/default “same root” fallback is unsound. The explicit internal interface update above is the simpler recommended choice and makes affected fixture adapters visible at compile time.

Also preserve disappearance provenance at this boundary. If opening an optional root reports absent, absence can be recorded. If a child previously returned by bounded enumeration disappears during its metadata/body acquisition, return positively observed SNAPSHOT_MOVED, not a raw not-exist error that `journal.scan` can mistake for an absent optional root (`internal/journal/audit.go:235–239`). This movement uses the existing four-attempt owner; unrelated I/O/type/limit errors remain fail-closed.

**Witnesses:** root replacement with identical moved children; empty state/staging parent replacement; a listed parent replaced before body read; special-file/FIFO replacement; child disappearance after successful enumeration versus an initially absent optional root; missing directory metadata from a fixture Source; and deterministic handle closure on success/body error/movement. Verify the stated four total attempts and preserved native byte/mode/mtime purity.
