PAUSE/UNPAUSE do not create tickets. KEEP/ADOPT require an existing canonical target at lines 324–329. The required C therefore cannot arise from a literal INIT→PAUSE→UNPAUSE→KEEP→ADOPT history alone. ## 2. MED — distinguish stable preflight projection agreement from pending recovery PRE/POST

**Plan evidence:** line 23 requires private projection agreement and says only the selected target D may differ; line 31 also uses this helper for recovery. Lines 44 and 54 correctly permit already-applied versus unapplied receipt posts after commit, but do not reconcile that with the helper's earlier strict contract.

**Counterexample:** crash immediately after a PAUSE receipt is linked, before its request-index and barrier posts. The newly linked receipt and required blobs are valid; request index/barrier are still their preimages. A helper that demands agreement with the latest linked receipt rejects this required recovery prefix. Demanding agreement only with the head's prior chain likewise rejects a later mixed prefix in which one post has already applied. Existing `journal/records.go:383–411` performs strict latest projection agreement, so calling that behavior and ignoring its error cannot fill the gap.

**Smallest amendment:** give the test helper two explicit uses. Stable preflight validates the complete committed base and exact private agreement (allowing only the selected controlled physical D divergence). Pending recovery validates the canonical base through the actual head, exactly one next linked receipt, all receipt/request/post/blob bindings and the descriptor relationship; for each affected destination classify exact recorded physical PRE/absence or exact POST/absence, allowing mixtures while retaining strict agreement for unaffected private projections. For KEEP, use the receipt's physical pre D rather than substituting canonical C. Third private values hold; third intent values remain preserved divergence. Derive a missing genesis/head from actual committed bytes where applicable. No Model, original Plan or cached expected bytes enter this recovery observation.

**Witnesses:** receipt-only and mixed-post PAUSE/UNPAUSE/KEEP prefixes resume from fresh handles with no original Plan; an unrelated private projection change and a third affected private value both hold. The same malformed ledger/blob must fail both observation uses. Keep this a finite test-only distinction, not a production Audit option.
