## Primitive boundary

- Constructor validates the exact resolved repository and matching live lock, pins the common/state/staging/destination parents and lock identity, and fails closed on wrong/closed/zero inputs. Test ownership comes from the harness; raw paths, Binding, same UID, fixture:true and flock never establish ownership or actor authorization.
- Serialize each operation with both session closure and the actual Lock.Close lifecycle. Hold the lock's lifecycle protection through the complete operation, not just a preliminary `closed` check or one syscall. Fix one lock acquisition order; concurrent session Close and Lock.Close must neither release exclusion mid-operation nor deadlock. Explicit Close reports joined release/handle failures.
- Closed stage names are exactly `active.json.tmp`, `active.json`, `a00` through `a10`, with their separate operation roles. Slot staging permits legitimate empty raw bytes; limits apply before allocation/create/write. Full writes, digest/length confirmation, strict file sync and directory sync are distinct success conditions. Partial/failed preparation never becomes a reusable successful stage token.
- Cross-parent publication consumes only session-owned stage identity plus an admitted destination role/name. Require exclusive link semantics. Preserve existing destinations of every type. No absolute path, separator traversal, alias or mutable caller-provided directory handle becomes destination authority.
- Checked replacement is limited to explicitly admitted mutable private projections; receipt history, content-addressed evidence/pins, request identity and the lock are never replacement/deletion targets. Controlled removal covers only the admitted barrier/stage roles. Existing intent-file overwrite/removal is excluded; an absent intent destination may be linked exclusively. Failures after successful link/rename/unlink/mkdir remain typed as effects already performed, with every failed required sync/cleanup retained. They do not imply a receipt was committed: J3-01 has no transaction sequence.
- Pin both parents and source identity during cross-directory native calls. Check observed directory/name replacement before effects. Preserve foreign entries on detected mismatch, including cleanup paths. This does not promise atomic check-and-rename/unlink against an unrelated writer; that remains outside the sole-writer fixture boundary.
- Observe device/filesystem and mount identity through retained descriptors, refusing ambiguity or mismatch. Equal st_dev alone is insufficient. EXDEV never invokes copy/unlink. Distinguish a successful link from successful destination-directory durability; source removal/rename also requires source-directory sync. New-directory durability includes the directory and its parent.

## Finite evidence required before completion

Use one finite table per primitive over its actual syscall/sync/close boundaries, with modest byte fixtures and deterministic hooks. No transaction phase runner is needed in this slice.

1. Session identity/lifetime: matching lock success; wrong repository, wrong lock, closed lock and zero session refuse; replaced lock/common/state/destination parent refuses; concurrent operation/Lock.Close/session.Close completes without descriptor reuse, early unlock, leaked handles or deadlock. Repeated Close preserves documented idempotence.
2. Stage: every admitted slot/role and representative invalid/traversal/NUL/overlong/alias names; absent/existing regular/symlink/FIFO/directory entries; zero bytes, bound and bound+1; partial/short writes; sync and Close failures. Existing foreign names/bytes remain unchanged and incomplete stages are not publishable.
3. Exclusive cross-parent link: absent destination success and same/different existing bytes all preserve exclusivity; source replacement and directory replacement hooks; no-follow symlink/FIFO cases; mismatched/unknown mount and late EXDEV; source descriptor/slot identity stays pinned. Observe both destination visibility and source retention.
4. Mutable private replace/remove and directory creation: exact expected pre/absence, already-applied state and observed third value; forbidden immutable/intent destinations; replacement/removal and child/parent sync failures; no recursive cleanup or foreign-entry deletion. Negative fixtures check foreign bytes, names and relevant metadata, not merely an error code.
5. Publication/error classification: inject failures before each effect and after successful effects/before every required destination/source sync; join simultaneous primary, cleanup and Close failures. Fresh handles verify whether each source/destination exists and which bytes it holds. No clean success on an unperformed sync and no 'nothing happened' result after a performed effect.
6. Compatibility/platform: existing LinkIn non-empty/empty/exclusive/error witnesses remain unchanged; unsupported platform/host is explicit refusal, never qualification. Actual interruption children, if introduced, require the repository's cleanup supervisor and descendant-interruption witness. Root alone runs the canonical gate.

These witnesses establish primitive behavior under stated assumptions, not whole-store crash recovery, physical power-loss durability, archive staging-layout acceptance, capacity/escrow, branch checks, historical acceptance or operator authorization.
