## Why the proposed arithmetic is sound

`Manifest.Value` (`manifest.go:87`) encodes a fixed metadata envelope and the canonical file-entry array; each entry uses `entryValue` (`manifest.go:70`). Sorting changes neither entry lengths nor separator count. With N entries, the exact LF-inclusive manifest length is the empty-files envelope length plus the sum of encoded entry lengths plus max(N-1, 0). Use the same metadata construction as production so optional digest/null and decimal/text encoding changes cannot drift.

`writeEntry` (`export.go:352`) constructs a regular-file PAX header with fixed mode and timestamp. Sharing that unchanged constructor and measuring `WriteHeader` on a fresh counting sink for each member counts both any emitted PAX extension and its padding plus the actual file header. A fresh writer avoids charging the previous member's padding twice. Do not close that header-only writer with an unwritten body; add body padding arithmetically and the archive trailer once.

The precise size contract should name the existing production quantities explicitly:

- `Files` = N = len(manifest.Files), excluding manifest.json and PAX extension entries, as existing ExportResult/CLI reporting does.
- `PayloadBytes` = sum of the supplied file-entry body sizes, excluding manifest.json.
- `ManifestBytes` = M, including its trailing LF.
- `TarBytes` = headerBytes(manifest.json, M) + round512(M) + sum(headerBytes(path, size) + round512(size)) + 1024.

These are costs of the supplied description, not proof that any described bytes or complete inventory exist. An empty file list is a useful arithmetic parity fixture even though it cannot constitute a verified store archive.

## Implementation boundaries retained by this PASS

Preserve the Identifier128 plus Path rules, reserved manifest.json rejection, unique paths and production path-size bounds. Apply the existing file-count, manifest-byte and exact-tar caps. Do not silently broaden archive acceptance or add a new inventory grammar through the sizing helper.

Claimed body length alone must not increase memory usage.
